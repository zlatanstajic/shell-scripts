# Repository Instructions

These instructions apply to every agent working in this repository.

## Before editing

- Read a file before changing it.
- Search all callers before changing a function, shared helper, CLI flag, or
  configuration key. Use `rg` or `rg --files` for discovery.
- Read [`CLAUDE.md`](CLAUDE.md) for detailed script behavior and architecture
  before making non-trivial changes.
- Preserve existing user changes and keep unrelated work out of the patch.

## Source ownership

- [`src/scripts/`](src/scripts/) contains user-facing Bash commands and the
  maintainer-only documentation generator.
- [`src/lib/common.sh`](src/lib/common.sh) contains shared behavior. Reuse its
  helpers instead of duplicating logging, confirmation, dry-run, or exit logic.
- [`src/completion/shell-scripts.bash`](src/completion/shell-scripts.bash) owns
  Bash completion for installed command names.
- [`install.sh`](install.sh) and [`uninstall.sh`](uninstall.sh) own symlink and
  completion installation. Never edit a generated or local `deploy/` copy.
- [`tests/`](tests/) contains the zero-dependency Bash test harness. Shared
  library and installer tests live at its root; per-script tests belong in
  [`tests/scripts/`](tests/scripts/).
- [`docs/`](docs/) contains the Jekyll/GitHub Pages documentation.
- [`assets/img/og-image.png`](assets/img/og-image.png) is generated by
  [`scripts/gen-og-image.py`](scripts/gen-og-image.py). Change the generator,
  then regenerate the PNG rather than editing the image directly.

## Bash conventions

- Match the existing script skeleton: shebang and metadata header, variables,
  `Help`, `GetArguments`, task functions, `Main`, then `RunScript Main "$@"`.
- Use PascalCase function names, two-space indentation, LF line endings, final
  newlines, and an 80-character target for shell files.
- Resolve `SCRIPT_NAME` and `SCRIPT_DIR`, source `../lib/common.sh`, then enable
  `set -u` in user-facing scripts.
- Offer `-h` / `--help`; use paired short and long flags where practical.
- Quote expansions and argument forwarding. Avoid `eval` and string-built
  commands; pass commands as argument arrays or `"$@"`.
- Route mutating operations through the established dry-run and confirmation
  helpers. Side-effecting scripts should support a safe preview when their
  existing contract does.
- Guard optional external tools with `command -v` and log a warning. Treat a
  tool as a hard dependency only when the command cannot perform its purpose
  without it.
- Keep configuration keys documented in [`.env.example`](.env.example), but
  never read, source, or write the repository's real `.env` file.
- Adding or removing a user-facing script also requires updating Bash
  completion and the installer/test expectations for the command list.

## Tests and verification

Run checks in proportion to the change. Before handing off a production script
change, run:

```bash
bash tests/run.sh
shellcheck src/scripts/*.sh src/lib/common.sh install.sh uninstall.sh
bash src/scripts/gen-docs.sh --check
```

Also run the affected script with `-h` and exercise its normal or dry-run path
on a Unix-like system when safe.

Tests must be isolated and non-interactive:

- Use `mktemp -d` fixtures and clean them with `trap`.
- Copy scripts and `common.sh` into a fixture tree when configuration is
  required; never source the developer's real `.env`.
- Scrub ambient configuration variables that could leak into a test.
- Use dry-run and assume-yes flags for scripts that can mutate the host.
- Capture subprocess output through a temporary file when a pipe could hang.
- Route functions that call `exit` through a subshell or `assert_exit`.

## Documentation and generated output

- The command reference between the generated markers in
  [`README.md`](README.md) and the full
  [`docs/_includes/command-reference.md`](docs/_includes/command-reference.md)
  are generated by [`src/scripts/gen-docs.sh`](src/scripts/gen-docs.sh). Never
  hand-edit generated command entries.
- When help text or flags change, update the script, run
  `bash src/scripts/gen-docs.sh`, and include both regenerated outputs.
- Keep the hand-maintained README, per-script pages under `docs/scripts/`,
  [`CONTRIBUTING.md`](CONTRIBUTING.md), and [`CLAUDE.md`](CLAUDE.md) synchronized
  with behavior changes.
- Use `zlatanstajic` as the canonical GitHub username in repository and GitHub
  Pages URLs.

## Git discipline

- Do not run `git add` unless the user explicitly asks.
- Never stage or commit changes on your own initiative.
- Do not discard, reset, or overwrite unrelated working-tree changes.
- If branch creation is requested, branch from `master` and use
  `issues/<issue-number>-<short-description>` (kebab-case).

## Secrets

- Never read or write `.env` files.
- Never expose passwords, tokens, decrypted environment contents, or other
  secrets in source code, tests, logs, generated docs, or chat output.
- Use environment variables for sensitive values and ask the user for access
  when a task requires a secret.
- Never use `git-crypt` to encrypt repository secrets.
